# Standard Operating Procedures

Step-by-step procedures for the recurring, judgment-sensitive parts of the acquisition process — where a checklist matters more than a system feature, and consistency matters more than speed.

## Index

| SOP | Covers |
|---|---|
| `Owner-Outreach.md` | Drafting and sending mailer follow-ups and PSA correspondence |
| `Due-Diligence-Review.md` | Reviewing and confirming a due-diligence flag |
| `Closing-Wire-Verification.md` | The non-negotiable phone verification step before any wire goes out |

## Relationship to `docs/BUSINESS_WORKFLOWS.md`

`BUSINESS_WORKFLOWS.md` describes the end-to-end process at a system level — what module handles what stage. These SOPs go one level deeper: the exact steps a person follows for a specific, recurring, high-stakes task. If the two ever disagree, treat that as a signal the docs need reconciling, not that one silently wins — flag it.

## Who owns updates here

Anyone following an SOP that no longer matches reality should raise it, not quietly work around it — an SOP that's out of date is worse than no SOP, since it creates false confidence that the process is documented and correct.
